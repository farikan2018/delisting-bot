# Delisting Short Bot — План і стратегія

## Ідея
Ловити анонси делістингу на Binance → в ту ж секунду відкривати шорт на біржі виконання
(MEXC або резерв) → сповіщати про відкриття/закриття угоди в Telegram + керувати ботом через Telegram.

---

## 1. Стратегія (торгова логіка)

### 1.1. Сигнал — детект делістингу
- **Джерело:** Binance Announcements CMS API (неофіційний, але стабільний):
  `https://www.binance.com/bapi/composite/v1/public/cms/article/list/query?type=1&catalogId=161&pageNo=1&pageSize=20`
  (`catalogId=161` = розділ Delisting). Дублювати офіційним фідом анонсів як резерв.
- **Підтверджувальний сигнал:** зміна статусу символа в `exchangeInfo` (torgівля → BREAK).
  Повільніший, але 100% надійний — використовуємо як крос-чек.
- **Poll:** кожні 1–2 с. Дедуп по `articleId` (щоб не спрацювати двічі).
- **Парсинг:** з заголовка витягуємо тикери (регулярка на кшталт "Binance Will Delist X, Y, Z").
  Один анонс = часто кілька токенів.

### 1.2. Фільтри входу (перед відкриттям шорта)
- Токен має перп на біржі виконання і він tradable.
- Немає вже відкритої позиції по цьому токену.
- Токен не в blacklist.
- **Anti-late-entry:** якщо ціна вже впала більше ніж на `MAX_ALREADY_DROP%` за останні
  N хв — пропускаємо (щоб не шортити саме дно перед відскоком). Налаштовується.
- Не перевищені ліміти ризику (див. 1.5).

### 1.3. Вхід
- Ринковий ордер (або агресивний лімітний із проковзуванням `MAX_SLIPPAGE%`).
- Розмір позиції `POSITION_SIZE` (USDT), плече `LEVERAGE`.
- Одразу виставити захисні ордери (SL / TP), якщо біржа підтримує.

### 1.4. Вихід (закриття)
Комбінований, спрацьовує перше з умов:
- **Trailing stop:** фіксуємо прибуток, коли ціна падає (основний механізм).
- **Take-profit:** закрити при `-TP%` (ціна впала на нашу користь).
- **Stop-loss:** закрити, якщо пішло проти нас на `+SL%` (пампить).
- **Max hold time:** примусово закрити через `MAX_HOLD` годин (щоб не платити фандинг вічно).
- **Funding-aware:** якщо накопичений негативний funding перевищує поріг — вихід.

### 1.5. Ризик-менеджмент
- `POSITION_SIZE` — макс. розмір на одну угоду.
- `MAX_CONCURRENT` — макс. одночасних позицій.
- `MAX_TOTAL_EXPOSURE` — стеля сумарної експозиції.
- `DAILY_LOSS_LIMIT` — kill-switch на день.
- `COOLDOWN` — не входити повторно в той самий токен.
- Ручний `/pause` і `/panic` (закрити все) через Telegram — завжди мають пріоритет.

## 2. Ризики й реальність (важливо!)

1. **MEXC міг відключити розміщення ф'ючерсних ордерів через API для роздрібу.**
   → Перевірити ПЕРШИМ ділом. Executor робимо абстрактним (через ccxt), щоб легко
   перемкнути на Bybit / Gate / BitGet, якщо MEXC не дасть ставити ордери.
2. **Конкуренція ботів + latency.** Найбільший рух — за перші секунди. Ми не завжди
   встигнемо першими. Тому anti-late-entry фільтр і реалістичні очікування.
3. **Funding rate** під час дампу сильно негативний → шорт платить. Тому max hold time.
4. **Ліквідність/спред** дрібних токенів → проковзування, ліміти позиції.

## 3. Архітектура

```
config.py           налаштування, ключі (з .env), дефолти
storage.py          SQLite: seen_articles, positions, trades, settings
binance_watcher.py  poll CMS API + exchangeInfo, парсинг → DelistingEvent
exchange.py         абстракція біржі (ccxt): markets, open_short, close, position, funding
strategy.py         рішення про вхід/вихід + risk-checks
executor.py         розміщення/супровід ордерів, reconcile при старті
telegram_bot.py     сповіщення + команди (aiogram)
main.py             async event loop, зв'язує все
```

**Стек:** Python 3.11+, `ccxt` (біржі), `aiogram` (Telegram), `aiohttp` (poll),
`SQLite` (стан). Все асинхронно.

**Стан у SQLite** — критично для надійності:
- `seen_articles` — дедуп анонсів.
- `positions` — відкриті позиції (reconcile з біржею при старті).
- `trades` — історія для звітів і /status.
- `settings` — редаговані через Telegram параметри.

---

## 4. Telegram

**Сповіщення:** сигнал знайдено → ордер відкрито (символ, розмір, ціна входу, плече) →
ордер закрито (ціна виходу, PnL, причина) → будь-яка помилка executor'а.

**Команди:**
`/status`, `/positions`, `/pause`, `/resume`, `/panic` (закрити все),
`/setsize <usdt>`, `/setleverage <x>`, `/close <SYMBOL>`,
`/blacklist <SYMBOL>`, `/whitelist`, `/config`.
